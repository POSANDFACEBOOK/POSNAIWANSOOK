# Caching — ทำไมตั้งแบบนี้

> ⚠️ **ห้ามใส่คอมเมนต์ลงใน `vercel.json`** — Vercel ตรวจ schema เข้มงวด คีย์ที่ไม่รู้จัก
> (รวมถึง `"//"` ที่หลายโปรเจกต์ใช้แทนคอมเมนต์) ทำให้ **deployment ล้มทั้งใบ**
> เคยพลาดมาแล้ว 12 ส.ค. 69 — config ไม่ขึ้น แต่เว็บยังเสิร์ฟของเก่าอยู่ เลยดูเหมือนปกติ
> คำอธิบายทั้งหมดจึงอยู่ในไฟล์นี้แทน

## เกิดอะไรขึ้น (9 ส.ค. 69)

Vercel หยุดให้บริการทั้งบัญชี — ทุก URL ตอบ HTTP 402 ทั้ง foodcost, HR,
trading-ai, fb-ads-manager พร้อมกัน ร้าน 7 สาขาใช้งานไม่ได้เลย

| ตัวชี้วัด | ใช้ไป | เพดานฟรี |
|---|---|---|
| Fluid Active CPU | 11 ชม. 57 น. | 4 ชม. |
| Fast Origin Transfer | 28.21 GB | 10 GB |

**Fast Origin Transfer** คือไบต์ที่วิ่งจาก origin (ฟังก์ชัน/ไฟล์) ไปยัง CDN
อะไรที่ CDN แคชได้ จะไม่วิ่งซ้ำ = ไม่นับ และไม่กิน CPU ของฟังก์ชันด้วย
การแก้จึงเป็นการทำให้ CDN แคชได้ ไม่ใช่การลดจำนวนผู้ใช้

## ต้นเหตุ 2 ตัว

**1. `/api/drive-view` ส่ง `Cache-Control: private`**

คำว่า `private` สั่ง CDN ห้ามแคช แคชได้แค่ในเบราว์เซอร์ 5 นาที
รูปในระบบมี **846 ใบ** และทุกใบเสิร์ฟผ่าน endpoint นี้ ทุกครั้งที่มีคนเปิดหน้า =
เรียกฟังก์ชัน → ดึงจาก Google Drive → โหลดทั้งไฟล์เข้าหน่วยความจำ → ส่งออก

**2. `/assets/*` ไม่ถูกแคชเลย**

วัดจาก production จริงได้ `public, max-age=0, must-revalidate` — Vercel **ไม่ได้**
ใส่ immutable ให้ไฟล์ที่มี hash โดยอัตโนมัติอย่างที่หลายคนเข้าใจ
ก้อน JS หลักขนาด **1.5 MB** จึงถูกดึงจาก origin ใหม่ทุกครั้งที่มีคนเปิดหน้า

## กฎที่ตั้งไว้

| เส้นทาง | ค่า | เหตุผล |
|---|---|---|
| `/api/drive-view` (ตั้งในโค้ด) | 1 ปี · immutable | 1 Drive id = เนื้อหาเดิมเสมอ · เปลี่ยนรูป = ไฟล์ใหม่ได้ id ใหม่ |
| `/assets/*` | 1 ปี · immutable | Vite ใส่ hash ในชื่อ เนื้อหาเปลี่ยน = ชื่อเปลี่ยน |
| ไอคอน / manifest | เบราว์เซอร์ 1 วัน · CDN 30 วัน | ชื่อไม่มี hash จึงไม่ใส่ immutable |
| `/sw.js` | ห้ามแคช | service worker ค้างบนเครื่องที่ติดตั้ง PWA แล้วแก้ยากมาก |
| ที่เหลือ (index.html, เส้นทาง SPA) | เบราว์เซอร์ 0 · CDN 5 นาที | HTML ชี้ไปยังชื่อไฟล์ที่มี hash ถ้าค้างจะล็อกคนไว้กับเวอร์ชันเก่า |

`/api/*` ตัวอื่นไม่ได้ตั้งกฎไว้ เพราะเป็น write / webhook / cron ทั้งหมด แคชไม่ได้
และไม่ใช่ต้นเหตุของทราฟฟิก

## กับดักที่ต้องรู้

**Vercel ใส่ header ของ *ทุก* rule ที่ตรง แล้วตัวท้ายทับตัวหน้า** ไม่ใช่ "ตัวเจาะจงกว่าชนะ"

rule ตัวสุดท้ายจึงต้องตัด `api/ assets/ sw.js` และไอคอน ออกจาก pattern ให้ครบ
ถ้าปล่อยให้มันครอบ `/assets/` ด้วย ค่า immutable ข้างบนจะถูกทับเหลือ 5 นาที
= ก้อน 1.5 MB วิ่งกลับไป origin ทุก 5 นาที ซึ่งคือปัญหาเดิมที่ config นี้มีไว้แก้

## วิธีตรวจว่ายังทำงานอยู่

```bash
curl -sI https://foodcost-eta.vercel.app/assets/index-<hash>.js | grep -i cache-control
# ต้องได้: public, max-age=31536000, s-maxage=31536000, immutable

curl -sI "https://foodcost-eta.vercel.app/api/drive-view?id=<drive-id>" | grep -i -E "cache-control|x-vercel-cache"
# ต้องได้ immutable · และยิงซ้ำครั้งที่สองต้องได้ X-Vercel-Cache: HIT
```

ถ้าเห็น `max-age=0, must-revalidate` บน `/assets/` แปลว่า config ไม่ได้ถูกใช้ —
ไปดูว่า deployment ล่าสุด **build ผ่านหรือเปล่า** (ล้มแล้วเว็บจะยังเสิร์ฟของเก่าต่อ
โดยไม่มีอะไรบอก)

## ยังลดได้อีกถ้าจำเป็น

รูปถูกย่อไว้ที่ 1280px (~200KB) ตอนอัปโหลด แต่เอาไปแสดงจริงแค่ 44–150px
ถ้าให้ `drive-view` ดึงรูปย่อจาก Drive (`thumbnailLink`) แทนไฟล์เต็ม จะลดไบต์
ตอนที่แคชยังไม่ติดลงอีกราว 10–20 เท่า แลกกับการเรียก Drive เพิ่มอีกจังหวะ
ยังไม่ได้ทำ เพราะควรดูผลของ caching ก่อน
